# NixOS configuration

The flake uses the dendritic pattern: `import-tree` loads every file below
`modules/`, and each file contributes one flake-parts option or leaf module.
Leaf modules are composed at the host outputs without local file imports.

The installer generates a NixOS configuration for each machine. Karl's standalone
Home Manager configuration is also available. Files are grouped by responsibility:

- `modules/hosts/laptop`: optional laptop services
- `modules/installed`: machine configurations generated by the installer
- `hardware`: generated hardware detection results
- `modules/profiles`: reusable system profiles
- `modules/users`: NixOS user declarations and Home Manager wiring
- `modules/home/karl`: Karl's Home Manager modules

## Validate and build

```sh
nix flake check
sudo nixos-rebuild switch --accept-flake-config --flake path:.#YOUR_MACHINE
```

The standalone Home Manager configuration can be built with:

```sh
home-manager switch --flake .#karl
```

## Fresh installation

Boot an **x86_64 NixOS live USB in UEFI mode**, connect to the internet, clone
this repository, and enter the checkout. Run:

```sh
sudo bash scripts/install.sh
```

The script asks for a unique machine name (such as `pc` or `thinkpad`),
`laptop` or `pc`, and a target disk. It displays the disk and requires an
explicit `ERASE /dev/...` confirmation. **All data on that disk is erased.**
Use a disk of at least 64 GiB and back up anything you need first.

It detects the current machine's hardware, generates a named configuration,
partitions and mounts the disk, enables swap, and installs with temporary
build files on disk. The laptop choice includes the lid/caffeine integration;
the PC choice omits it. Both include the same desktop and user setup. Dedicated
GPU drivers or other hardware-specific features may still need configuration.

When it finishes, reboot and remove the USB. Log in as `karl` / `12345`, then
run `passwd`. Your configuration is in `~/.config/nixos`. For a machine named
`pc`, future updates are:

```sh
cd ~/.config/nixos
sudo nixos-rebuild switch --accept-flake-config --flake path:.#pc
```

Commit the generated `hardware/pc.nix` and `modules/installed/pc.nix` to keep
that machine in the repository. Use a new name when installing another
machine. Names such as `laptop` and `pc` are available.
If installation fails after partitioning, it prints a retry command; use that
command while the mounts remain in place, rather than repartitioning.

The script never automatically reboots. It requires an unmounted target and
an unused `/mnt`; it will not run from the installed OS. No password preparation
script is needed. To run its non-destructive checks: `bash scripts/test-install.sh`.

### Installer memory and speed

The install script partitions first and enables swap before building the system.
The pinned `disko-install` builds the entire system in the host store before
formatting and explicitly skips swap. On a live ISO that store may be in RAM.
`nixos-install --root /mnt` builds into the target store, and the script
also puts temporary build files on disk and enables swap before that build.
See [Disko's installer implementation](https://github.com/nix-community/disko/blob/master/disko-install).

Accept the flake's Noctalia cache so available binaries can be downloaded.
The script limits builds to one job with two cores. To distinguish memory
pressure from disk capacity or a slow source build, check `free -h`,
`swapon --show`, `df -h / /nix /mnt/nix /mnt/persist`, and
`sudo dmesg | grep -iE 'out of memory|oom|killed process'` in another terminal.
The tmpfs `size=4G` is a limit, not a reservation of 4 GiB RAM.

## Storage

Each installation uses 1 GiB EFI, 16 GiB swap, Btrfs subvolumes for `/nix`
and `/persist`, and tmpfs for `/`. Only the paths listed in
`modules/profiles/ephemeral-root.nix` survive reboot. Userborn keeps passwords
in the preserved `/var/lib/nixos/users` directory, so `passwd` changes persist.
Noctalia's runtime state is also preserved.

## Niri shortcuts

On the laptop, the coffee-cup button at the right end of the bar toggles caffeine.
When highlighted, it prevents idle actions and tells logind to ignore lid closure.
Turn it off to restore normal lid handling. The control-center caffeine toggle
and `noctalia msg caffeine-toggle` have the same behavior. The inhibition ends
when Noctalia exits, so it does not persist across logout or reboot.

The laptop-only `caffeine-lid` user service follows Noctalia's logind inhibitor.
Noctalia itself uses the unmodified cached package. Rebuild with
`--accept-flake-config` to accept the binary caches declared in `flake.nix`.

`modules/home/karl/niri-config.kdl` uses zero window gaps and Noctalia's
[recommended compositor integration](https://docs.noctalia.dev/noctalia/compositor-settings/niri/),
including rounded windows, floating settings, activation support, blur, and the
overview backdrop. `Mod` is Super in the normal desktop session.

| Shortcut | Action |
| --- | --- |
| Mod+Return / Mod+Q | Terminal / close window |
| Mod+arrows or H/J/K/L | Focus column or window |
| Mod+Shift+arrows or H/J/K/L | Move column or window |
| Mod+1–9 / Mod+Shift+1–9 | Focus workspace / send window there |
| Mod+Page Up/Down (add Shift to move window) | Previous/next workspace |
| Mod+Tab | Last workspace |
| Mod+Ctrl+arrows (add Shift to move column) | Focus monitor |
| Mod+F / Mod+Shift+F | Maximize column / fullscreen |
| Mod+V / Mod+Shift+V | Toggle floating / focus floating or tiling |
| Mod+R / Mod+Shift+R | Cycle width / height presets |
| Mod+Minus/Equal (add Shift for height) | Resize width by 10% |
| Mod+C / Mod+[/] | Center column / move window into or out of adjacent column |
| Mod+O / Mod+Shift+Slash | Overview / shortcut overlay |
| Print / Ctrl+Print / Alt+Print | Region / screen / window screenshot |
| Mod+Space / Mod+S | Launcher / control center |
| Mod+Shift+Comma / Alt+Tab | Noctalia settings / window switcher |
| Mod+Ctrl+V | Clipboard history |
| Mod+Ctrl+L / Mod+Escape | Lock / session menu |
| Mod+Shift+E | Quit Niri with confirmation |

Volume, microphone mute, brightness, and media keys also work while locked.
Validate changes with `niri validate --config modules/home/karl/niri-config.kdl`.
